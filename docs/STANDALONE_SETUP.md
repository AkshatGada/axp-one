# Standalone repository setup

All AXP application code, fonts/design assets, contracts, screened wallet
evidence, V1–V3 public results, replay bundles and pinned native payment source
belong in this repository. No runtime module imports another local project.
Old absolute paths in research/provenance documents describe history, not setup.

## 1. Present the recorded demonstration

Use Node 22.18 or newer (the `engines` field in `package.json`: native SQLite plus
TypeScript type stripping); Node 25.5 is the tested runtime. From the repository root:

```sh
npm run demo:v3:replay
```

Open `http://127.0.0.1:8794`. No npm install, API key, wallet, upstream database,
Docker, Codex session or Solana sandbox connection is required for recorded
replay. Recorded settlement is hosted Solana sandbox evidence, not new execution.
An occupied port can be changed with `AXP_V3_PORT=8795`.

The standalone backup remains `artifacts/v3/offline-presentation/` and its ZIP.
Original V1/V2/V3 evidence and captures are not regenerated by this setup.

## 2. Install the separate frontend workspaces

The marketing app and MVP frontend are separate apps inside the same repo:

```sh
pnpm install --frozen-lockfile
pnpm --filter @axp/marketing dev
pnpm --filter @axp/product-ui dev
```

They use this repository's `design-system` workspace. No personal-site or old
AXP checkout is required. Their final design/build acceptance remains owned by
the frontend specialist; consolidation does not certify unfinished frontend work.

## 3. Configure optional actual model use

Recorded replay needs no credentials. For an explicitly approved live run,
copy `.env.example` to `.env.local` and supply `JEV_API_KEY`; the older
`TYPESAFE_API_KEY` name remains supported. Process environment values work even
when `.env.local` does not exist. Never put a provider key in a client-side
`NEXT_PUBLIC_*` variable.

Live calls stay operator-enabled and subject to frozen admission limits. Setup
is not permission for another experiment, payment or reset of completed runs.

The optional organic-agent CLI uses `codex` from `PATH`, not a Mac application
bundle. Install and authenticate your own compatible CLI separately; use
`AXP_CODEX_BIN` for an explicit executable override. See the
[official CLI setup example](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex).
Recorded organic answers need neither CLI installation nor a signed-in account.

Existing videos are included. Optional re-encoding needs installed `ffmpeg`
and `ffprobe` on `PATH` (or `AXP_FFMPEG_BIN` / `AXP_FFPROBE_BIN` overrides),
not Homebrew specifically. Capture inputs are explicit absolute directories
named `axp-v3-capture.<suffix>` (or the corresponding V2/Phase5 prefix),
wherever the operator places them. Do not re-encode over preserved evidence.

## 4. Rebuild the exact payment SDK without another checkout

Only needed for native payment operations and native SDK tests, not replay:

```sh
npm ci --ignore-scripts --no-audit --no-fund --prefix tooling/payment-sdk
node scripts/payment-spike/phase4-sdk.mjs --acquire
```

`vendor/pay-kit/` contains the exact 67 tested runtime TypeScript modules from
commit `c294f8903f18efc746584e3cc2961d6033b8365c`, original MIT notice, package
manifest, upstream lockfile and locked metadata for 72 runtime dependencies.
The builder checks source and downloaded archive integrity and requires emitted
module hashes to match the previously tested SDK. It never builds the entire
upstream workspace. Output is ignored `local-state/phase4-sdk`.

The compiler and semver tool are separately lock-pinned in
`tooling/payment-sdk`. `AXP_PAYMENT_SDK_ROOT` can name an isolated output
directory; it is resolved relative to the repository, not another checkout.
With the dependency store already available, `--finish` performs the build
without downloading packages. Initial installation still needs the npm registry.

## 5. Local disposable wallet storage

The approved existing disposable test wallets were copied without changing
identities into owner-only, ignored `local-state/secrets/test-wallets.json`.
Default signing no longer reads the old access-core checkout. On another
machine, transfer this file separately over a private channel, preserve mode
`0600`, or supply `AXP_TEST_WALLET_PATH` to an approved private local file.

The explicit import helper is:

```sh
node scripts/setup/import-test-wallet.mjs /path/to/approved-test-wallets.json
```

It checks file permissions and key format, refuses to replace a different
existing wallet, and never signs, broadcasts or prints key material. Retaining
test wallets in Git would expose signing authority; provider "test" credentials
can also incur usage. Neither belongs in a pushable history.

Recorded public receipts are committed; SQLite databases, publisher signing
secrets, private spending vouchers and local financial intents are not. Do not
recreate closed channels or replay signing commands after a fresh clone. To
resume private obligations, transfer the private state separately; public replay
does not require it.

## 6. Verify before a future push

```sh
node scripts/setup/check-repository.mjs
npm test
node scripts/demo/v3-replay-check.mjs artifacts/v3/replay
```

The explicit replay-check path is read-only: it neither regenerates the bundle
nor overwrites its saved report. `v3-preservation.mjs --check` is additionally
used on the original working checkout, whose private-state preservation manifest
cannot be fully verified in a public clone without those ignored private files.

The check rejects machine-specific runtime paths, external source symlinks,
changed vendored source, private files in the index and recognizable provider
credentials. It prints paths, never matching secrets. It is a focused guard,
not a comprehensive secret scanner or production audit.

ContextHint's screened V2 export and vectors already reside here. Optional
maintenance/export scripts can read the authorized original corpus, but ordinary
V3 retrieval, laboratory and replay do not depend on that database. No clone,
source writes, recollection or embedding generation is part of standalone setup.

No push, deployment, new model call, transaction or wallet generation is
authorized or performed by consolidation.
