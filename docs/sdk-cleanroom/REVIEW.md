## Concrete public-contract ambiguities / limits

The preflight gaps remain public-contract issues, not evidence of integration failure:

1. **Size/sanitization:** SDK 1,200 versus baseline composer 1,600/API 4,000; app resolves this explicitly by skipping ads without truncation, warning users and requiring opt-in. Free-text sensitivity is not automatically detected.
2. **Expiry/orphans:** integer `expiresAt` units remain unspecified publicly. App assumes epoch milliseconds; successful actual placement is compatible with that assumption, not a general unit guarantee. Unknown timeout reservations rely on exchange expiry; no undocumented lookup/recovery API is invented.
3. **Error/failure detail:** SDK collapses non-2xx bodies to `http_error`/status; restriction canonicalization and validated `failRender` schema remain unspecified. App strips HTTP status from placement diagnostics (`axp-integration.js:153–154`); this reduces debugging specificity but does not break fail-open behavior.
4. **Observation limits:** SDK checks insertion/disclosure, not viewport/occlusion or independent creative-hash recomputation; link visibility is not separately checked. Main observed the card initially below the scrollable log viewport and reached it by keyboard scroll. Source appends the slot after its answer scroll (`public/app.js:37,81–87`), with no subsequent automatic scroll. Nonblocking discoverability limitation for this insertion-receipt contract, not proof of viewability.
5. **Receipt validation/cache:** SDK server validates selected bindings/shape, not cryptographic authenticity; browser acknowledger caches any fulfilled post. This app rejects non-OK HTTP before caching and checks accepted/synthetic metadata, so normal tested transport failures remain retryable. An anomalous HTTP-200 invalid/non-synthetic response could be cached before the app's post-check (`public/sponsorship.js:57–66`), making its retry ineffective; not reproduced on the valid fixture path and not a demonstrated local blocker.
6. **Modes:** public types admit sandbox/arbitrary strings beyond README's principal synthetic/devnet paths. This app only renders synthetic awards; no unsupported financial/network outcome is claimed.

## Nonblocking scope limitations and final disposition

- App session/turn/token bindings are explicitly memory-only (`axp-integration.js:38–39,60–69,83–89`). Refresh/reset, one-hour expiry, another tab or app restart can remove receipt reconciliation access. Exchange restart/replay tests do **not** prove durable app recovery. Appropriate to this tab-local fixture; not a durable integration guarantee.
- Browser evidence is supplied by Main and visually corroborated by the inspected screenshot, not an independent interactive browser run. No exhaustive accessibility, mobile, production-security or real-model-quality approval is implied.
- Harness names referring to a signed receipt establish stored receipt/signature data and ledger replay through the actual SDK, not independent cryptographic signature verification.
- The optional additional lost-response/cap probe considered during review was not executed, following Main's request to finalize without expanding coverage. Their NOT OBSERVED labels above are intentional, not passing assertions.

Review complete. No required SDK/app change identified for this bounded exercise; retain the documented limitations and do not promote this verdict to production, human-viewability, real-provider or payout claims.
